# IQ1 GPU-free performance preparation — 2026-08-21

Status: implemented and compile-validated on server60 (CPU-only, no GPU
contact). **No performance claim is established** — every number here is a
source-level expectation. The gates below must pass in an authorized GPU
window before any of this reaches a candidate image.

## Why

Measured Unsloth UD-IQ1_S/IQ1_M decode (40.80 / 44.79 engine tok/s) runs at
roughly half the Antirez GGUF-TP result (76.7 tok/s). Off-GPU source review
attributed the gap hypothesis-wise to implementation quality rather than
serialized size: the IQ2_XXS/Q2_K kernels received measured DP4A, DwarfStar,
and grouped-MMA tuning, while the IQ1/IQ3/MXFP4/Q4_K/Q5_K/Q6_K kernels were
correctness-validated only.

### 1. Parity-split IQ1 grid tables (`iq1_iq3_tables.cuh`)

The hot path previously consumed each 32-bit grid word through
`pack_iq1_grid_parity` — 8 shifts + 8 ORs per dot product — then multiplied
the packed bytes by the scale code (16 LOP3s). Two changes:

- Generated `kIq1SGridEven[2048]` / `kIq1SGridOdd[2048]` at table-generation
  time, byte-identical to `pack_iq1_grid_parity(grid, 0/1)`. Verified against
  the packing function on spot entries; the generator IS the packing function.
- Moved `kIq1SGrid`, both split tables, `kIq3XXSGrid`, and `kIqSigns` from
  `__constant__` to `__device__` storage. Constant-bank reads serialize when
  lanes in a warp read different addresses; every lane reads a different
  table index here, so the cached-global path (`LDG.E.CONSTANT`, L1-backed)
  is the correct choice.

### 2. Hot-loop consumption (`iq1_iq3_matvec.cu`, `iq1_grouped.cu`)

Raw/indexed kernels now index the split tables directly; the grouped kernel
stores pre-split words in shared memory at tile-load time, so fragment
decoding inside the MMA loop is one table word plus the scale multiply.
Net removal: ~24 integer ops per 32-value dot in raw/indexed, ~16 per
fragment in grouped.

### 3. Q4_K/Q5_K vectorized group dot (`q456_k_matvec.cu`)

Q4_K/Q5_K blocks are 144/176 bytes, so every quant segment is 16-byte
aligned by format geometry. The group dot now:

- loads the 32-byte quant window as two `uint4`s (was 32 byte loads),
- applies the Q5 high-bit plane branchlessly:
  `packed |= (load_u32(block+16+4p) >> group_index & 0x01010101) << 4`
  (was a per-byte load + data-dependent branch; the bit-plane-per-position
  semantics `high_bits[element] bit group_index` are preserved exactly),
- keeps scale/min decode and the d/dmin accumulation identical.

Q6_K keeps byte loads: its 210-byte block stride cannot guarantee alignment
for wider loads, and it covers only shared-down (one op/layer).

## Expected effect (hypothesis, not measurement)

Decode is dominated by weight streaming of the routed experts. The IQ1_S
gate/up path previously spent a large share of its inner loop on integer
bit manipulation between 1-bit table lookups and DP4A; removing ~24 ops per
dot and taking table reads off the serialized constant path should raise
the achieved bandwidth of the ~19.9–21.3 GiB/rank routed payload toward the
IQ2_XXS kernels' measured ~346–358 GB/s class. The Q5_K win additionally
covers shared gate/up and `q_a` partitions. Whether this closes a meaningful
fraction of the ~2× decode gap is exactly what the pending GPU gates must
answer; if kernel throughput was not the binding constraint (e.g. the
mixed-linear launch/intermediate overhead hypothesis dominates instead),
these changes will show flat and the next seam is the per-call
activation-quantize/concatenate chain in `GGUFDSV4LinearMethod`.

## Rejected / deferred in this pass

- Q6_K and IQ3_XXS vectorization: block strides 210/98 break 4-byte
  alignment; paired-block funnel-shift loads add risk without measurement.
- `multiply_packed_bytes` elimination in grouped MMA: the scale multiply
  cannot fold into activations (shared per tile, not per row) and int8
  overflow forbids hoisting it out of the dot.
- Mixed-linear intermediate-tensor/workspace reduction: behavior-affecting
  production change, deferred until the timing harness attributes it.
